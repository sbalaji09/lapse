# Bedrock LLM provider

## Goal

Run Channel B and the verifier through Amazon Bedrock without changing their
callers. Preserve the local OpenAI path and disk-cache replay.

## Configuration

- `LAPSE_BACKEND=local` (default): OpenAI models.
- `LAPSE_BACKEND=aws`: Bedrock Runtime Converse in `AWS_REGION`.
- `BEDROCK_MODEL_FAST`: extraction model, default Amazon Nova Lite.
- `BEDROCK_MODEL_VERIFY`: verifier model, default Amazon Nova Pro.
- `AWS_BEARER_TOKEN_BEDROCK`: the Bedrock API key used by boto3 for local
  development. No IAM profile or access-key pair is required.

OpenAI is an explicit fallback: switch `LAPSE_BACKEND` back to `local`. Bedrock
errors do not silently resend clinical text to OpenAI because that would break
the intended AWS/BAA boundary.

## Provider seam

`engine.llm.call_json` and `run_batch` keep their current signatures. In AWS
mode they:

1. Map the fast/verifier logical model to its configured Bedrock model ID.
2. Call `bedrock-runtime.converse`.
3. Force a `return_json` tool whose input schema is the caller's JSON schema.
4. Read the tool input as the structured response.
5. Record Bedrock input/output token usage in the existing stats object.

Batch calls share one boto3 client and use `asyncio.to_thread` under the
existing concurrency limit. This avoids adding an async AWS dependency.

## Cache contract

OpenAI keeps its existing cache keys so warmed demo caches remain valid.
Bedrock keys include both `bedrock` and the effective Bedrock model ID. Changing
Nova models therefore cannot return a response generated by the previous
model.

Local cache storage remains `.cache/llm`. Moving it to S3 is a separate AWS2
step.

## Verification

- Mocked Converse tests cover request shape, structured output, token usage,
  cache hits, model swaps, batch ordering, and explicit OpenAI fallback.
- Offline mode must inspect the cache before constructing either provider
  client.
- The existing Channel B/verifier tests and full suite must remain green.
- A live Bedrock smoke requires a Bedrock API key plus model access in the
  configured region; no live call is required for unit tests.

On 2026-09-26, synthetic live smokes passed through Converse for both configured
defaults: Nova Lite (fast path) and Nova Pro (verifier path).
